v1 输在哪

v1 每张卡都穿同一件衣服：3px 黑边 + 5px 硬阴影。
调研原话：「重边框和亮色铺满每一屏，认知负荷会累加」。

而 v1 还漏了一件事：DESIGN.md §5 写的是「工具卡片：可折叠」， v1 全展开，等于把唯一能解决密度的那个功能给丢了。

B+ 的全部规则

越危险 / 越少见的帧 → 越重
越密的字         → 越轻

W1 轻  2px 边 · 无阴影 · 行高 1.7   ← 正文
W2 中  3px 边 · 4px 硬阴影          ← 工具卡 / 按钮
W3 重  3px 边 · 6px 硬阴影 + 高饱和  ← 顶栏 / 危险命令

一个视觉簇里只允许一处 W3。

密集问题的两个解法

· 工具卡默认折叠成一条 ribbon。这本来就是 §5 的功能，v1 给漏了。默认状态下一屏能看完 3~4 次调用。
· 助手正文拿最轻的档。全屏最密的字配最轻的框 —— 野兽派在这一块主动退让，把「重」全让给状态和危险。
· 重量本身变成信息量。余光扫过去，最重的两块永远是「顶栏」和「危险命令」，不需要读。

为什么这个方向对这个产品不只是审美

工具卡里跑的是 rm -rf / git push --force。DESIGN.md §6.2 缓解措施 #4 要求危险命令高亮。
高饱和纯色 + 硬边框是余光可扫的告警形态。柔和阴影做不到这件事 —— 阴影要你「看」才能读出来，色块不用。
对一个 allowedTools 里有 Bash 的工具来说，这是安全可及性，不是装饰。
