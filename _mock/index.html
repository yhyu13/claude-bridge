6 个 demo 用完全一样的内容——同一段 2026-10-10 的真实调试（模型切换 + close 竞态）， 同一个工作目录、同一个模型、同一批工具卡片。并排看才有意义。

plan 与完整设计规则 → _mock/PLAN.md ｜ demo 均为零依赖单文件，双击即开 ｜ 它们没有动 web/ 的任何一行

为什么是这 6 个：你要的三个（浮雕 / 新野兽派 / 透明玻璃）都在，另加终端控制台（这个产品真正的原生语言）和可信轨迹（它最该有但现在没有的东西）。 B+ 是 v1 的修正版，也是目前选定的方向。
动手前先记住一条约束：DESIGN.md §5 是功能规格，列的东西一个都不能丢 （顶栏 / 消息流 / 工具卡片 / 成本条 / 输入区 / 中止 + 紧急停止 / 危险命令高亮）。 §5 末尾「不做代码高亮」是 MVP 边界，不是审美偏好——要动它是功能决定，得单独讨论。

选型已定：走 B+（野兽派信号层）。

理由不是「最好看」，是差异化。终端控制面是全场最不独特的——Claude Code 像它、Warp 像它、每一个 agent console 都像它。 「和所有人都不一样」这件事上，野兽派是唯一真正空着的一块地。

唯一保留的担心：这个产品的主界面恰好就是密集数据面板。B+ 用「越危险越重、越密的字越轻」这条规则处理它， 但真正的判据是在你手机上读十分钟会不会累——这个我验不了，只能你验。
B+ 还没解决的那件事：危险命令在 B+ 里只是最丑的一块，点了照跑。 DESIGN.md §6.2 缓解措施 #4 只做到「事后高亮、不阻断」，而 allowedTools 里有 Bash。要真正堵上得配 E 的执行前拦截，那是后端改动。
