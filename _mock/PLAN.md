# 前端视觉方案 —— 5 个方向的 plan

`DESIGN.md` §5 是**功能**规格，它列的东西一个都不能丢：

| 顶栏：工作目录 / 模型 / 累计成本 / 连接状态点 | §5 |

§5 末尾写着「不做 Markdown 渲染引擎、代码高亮、文件树」——那是 **MVP 边界**，不是审美偏好。真要上代码高亮，那是功能决定，得单独讨论，本轮不碰。

**5 个 demo 用的内容完全一样**（同一个工作目录、同一个模型、同一段工具调用），这样并排看才有意义。内容取自 2026-10-10 那次真实调试（模型切换 + close 竞态），不是随手编的假数据。

## 1. 参考物：哪些是**真的在跑**的东西，不是 Dribbble 摆拍

| 方案 | 照抄对象 | 我从哪拿到的规则 |

## 2. 五个方向

### A. 液态玻璃 Liquid Glass → `01-liquid-glass.html`

**核心**：`backdrop-filter: blur(20px) saturate(180%)`。`saturate` 是大多数人忘写的那半个效果——高斯模糊会把颜色平均掉，纯 blur 出来是脏塑料，push 饱和度才像玻璃。底色约 8% 白（纯透明只有模糊、没有面），1px 半透明白描边定义边缘。

**铁律**（抄自多个来源，冲突的地方按这条）：
- 同时最多 3 个毛玻璃面，叠 blur 会互相污染且掉帧
- **长文本不放玻璃上**——玻璃没有稳定对比度。所以消息正文必须实底
- 必须有实色 fallback（`@supports` + `prefers-reduced-transparency`）
- 透明度要有**梯度**：越靠上层越透，制造空间感

**诚实的代价**：Apple 自己因为可读性被骂，在 iOS 27 把默认透明度**降下来**了，还加了滑块让用户自己调浓淡。所以这方案天生要配一个「浓淡」开关。

**适合**：这个产品的一天大半时间在**看文字**（读 Claude 的回答、看文件路径）。玻璃适合顶栏、输入框、面板这类 chrome，不适合正文。

---

### B. 新野兽派 Neo-Brutalist → `02-neo-brutalist.html`

**核心**：整个设计系统就三条 CSS 声明。

```css
border: 3px solid #000;
box-shadow: 4px 4px 0 #000;   /* blur 必须 0，这是承重的那一行 */
border-radius: 0;
```

按下时 `translate(4px,4px)` + 阴影缩到 0，像把按钮按进纸里。8px 间距刻度。

**为什么是这个产品值得占的方向**：工具卡片里跑的是 `rm -rf`、`git push --force` 这类东西。`DESIGN.md` §6.2 缓解措施 #4 要求「危险命令高亮」。高饱和纯色 + 3px 黑边，是**在余光里就能扫到**的告警形态——柔和阴影做不到，阴影要你「看」才读得出来，色块不用。对一个 `allowedTools` 里有 Bash 的工具来说，这是安全可及性，不是装饰。

**v1 的死穴**：每张卡都穿同一件衣服，而调研原话是「重边框和亮色铺满每一屏，认知负荷会累加」。而且 v1 工具卡全展开，**把 §5 本来就写了的「可折叠」给丢了**——那是唯一能解决密度的功能。

---

### B+. 野兽派信号层 → `06-brutalist-signals.html`（**选定方向**）

v1 不是调色问题，是规则错了。B+ 换了一条规则：

> **越危险 / 越少见的帧，越重；越密的字，越轻。**

| 档 | 规格 | 用在哪 |
|---|---|---|
| W1 轻 | 2px 边 · **无阴影** · 行高 1.7 | 助手正文（全屏最密的字） |
| W2 中 | 3px 边 · 4px 硬阴影 | 工具卡 ribbon / 按钮 |
| W3 重 | 3px 边 · 6px 硬阴影 + 高饱和 | **只有**顶栏和危险命令 |

一个视觉簇里只允许一处 W3。密集问题的两个解法：

1. **工具卡默认折叠成一条 ribbon**（§5 本来就写了「可折叠」），默认一屏能看完 3~4 次调用
2. **助手正文拿最轻的档**，野兽派在这一块主动退让，把「重」全让给状态和危险

对比度：#111 on #F4EFE4 = **15.8:1**，#111 on #FFDE43 = **12.4:1**，全项 WCAG AAA。

**仍欠的一件事**：B+ 只解决了「读起来累」，没解决「点下去会不会出事」。危险命令在 B+ 里仍然只是最丑的一块，**点了照跑**。要堵上得配 E 的执行前拦截，那是后端改动。

### C. 浮雕 Relief（新拟物 2.0）→ `03-relief.html`

**这一条是对「浮雕风」的修正，不是照抄。** 调研里对新拟物的一致评价是它**失败了**，原因写得很清楚：

> 控件和背景同色，只靠柔和阴影定义 → 一个主动作按钮和它背后的背景长得一模一样，可读性归零。

所以这个 demo 的立意是：**保留浮雕的实体感，但把对比度用描边和明暗阶差补回来**。单一光源（左上），凸起用亮/暗双向阴影，凹陷用内阴影，同时所有可点元素带 1px 描边和高对比文字。

**诚实的代价**：即使修正过，浮雕在低亮度环境下仍然费眼——暗部层次全靠阴影堆出来的，手机户外基本没法用。它适合**夜间模式**。

---

### D. 终端控制台 Agent Console → `04-console.html`

**核心**：`#000000` 纯黑（OLED 像素熄灭 = 无限对比度），等宽字，强调色（青 / 琥珀 / 品红）直接浮在屏外。信息密度拉到最高，一屏塞下完整的工具调用链。

**为什么是这个产品的「原生语言」**：它驱动的东西就是一个终端会话。Claude Code 的输出本来就是 NDJSON，本来就是等宽字体，本来就是 `--model` / `--resume` / `400 model platform is not recognized` 这种行。把它包装成消费级气泡，等于**翻译了一遍不需要翻译的东西**。

**诚实的代价**：等宽字在中文里难看（`C:\code` 这种路径反而很清楚）。可读性靠密度换的，不适合长时间阅读。

---

### E. 可信轨迹 Trust Trail → `05-trust-trail.html`

**这一条不在你点的三个里**，但我认为它对这个产品最重要，所以必须做。

**核心**：2026 的 agentic UI 共识是「AI 在自主执行时，界面必须让意图、推理、可控性三样在**动作发生当下**可见」。这个产品握着你的开发机完整 shell（`DESIGN.md` §6.1 写得很直白），那视觉设计的头号任务就不是好看，是**让你随时看得见它正在干什么、以及能立刻拦住它**。

所以这一版把**每一个 agent 动作都变成一条可检视、可暂停、可回溯的轨迹**，而不是一条聊天气泡。危险命令在**执行前**就要拦一次，不是执行后标红。

**诚实的代价**：它更重、更慢、占更多屏。如果你要的是「好看」，这一版会让别人觉得你还没做完。

## 3. 选型结论（2026-10-10 已定）

**走 B+ 野兽派信号层。**

理由不是「最好看」，是**差异化**。我这一版原先把 D 排第一，理由是「原生语言 + 无障碍最稳 + 信息密度最高」——但那三条恰好是「和别人一样」的三条。终端控制面是全场最不独特的：Claude Code 像它、Warp 像它、每一个 agent console 都像它。**「和所有人都不一样」这件事上，野兽派是唯一真正空着的一块地。**

需要修正我之前对现状的描述：「没人把野兽派和代码放一起」不准确——放在一起的多，**放在一起当主力工作界面**的少。调研原话：「大多数采用发生在落地页、专题站、Hero 段和引导页，而不是密集数据面板。」这块地是空的，值得占。

**保留的一条担心**：这个产品的主界面恰好就是密集数据面板。B+ 用「越危险越重、越密的字越轻」处理它，但**真正的判据是你在手机上连读十分钟会不会累**——这个我验不了，只能你验。

**仍欠的一件事**：B+ 只做了视觉层的「危险」，没做行为层的「危险」。`DESIGN.md` §6.2 缓解措施 #4 只到「事后高亮、不阻断」，而 `allowedTools` 里有 Bash。要真正堵上得配 E 的执行前拦截，那是 `claude-session.js` 的改动。
